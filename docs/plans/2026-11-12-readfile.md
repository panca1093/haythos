# readfile: how Alfred reads code (plan, 2026-11-12)

## Why

In chat `chat-27e59fbac8ba` (2026-11-11), one prompt made 9 model requests. They used 223,595 input tokens with zero cache hits, after 19 whole-file `fs.read` calls (214 KiB). Every result was replayed in full on every later request.

Rule 1 stays: Alfred reads on the kernel's own loop, and runtime tools stay off (`--tools ""`). Instead we copy what Hermes, Claude Code and Codex do (source-level research, 2026-11-12):

| Pattern | Taken from |
|---|---|
| Read by offset/limit with line numbers, a char cap, and `next_offset` | Hermes, Claude Code |
| Search with ripgrep; returns file names by default, with small limits | Claude Code, Hermes |
| Cap each tool result when it is recorded; never rewrite history later | Codex |
| A stable `prompt_cache_key` per conversation on the Responses route | Codex, Hermes |

What we leave out, and why:
- **Re-read dedup:** Claude Code removed its stub in 2.1.317.
- **Spill to file:** with every result small at record time, it is not needed.
- **Pruning or summarising old tool results:** it breaks the cache, and Hermes has it off by default.

## Decisions

1. **Tool names are a contract, named by capability: `file.list`, `file.read`, `file.search`.** The Go package is an implementation detail. `app.Tools` is already the port, and the registry dispatches by name, so no new interface is needed. No code outside config may compare a tool name. That removes the `"fs.read"` check in `adapters/model/chatgpt`. *(Claude's call: the names.)*
2. **Search runs the `rg` binary only, with no Go fallback.** It uses `exec.CommandContext` with fixed argv and never a shell, the same as `vmhealth`. If `rg` is missing, the tool says so. The binary path comes from config, defaulting to `rg` on PATH.
   - With a single implementation there is no searcher interface. Tests use the real `rg` and skip when it is absent.
   - Not a shell from the kernel's loop: the model passes a pattern, never a command.
3. **Generic record-time cap in `app.appendResult` for every tool, MCP included.**
   - Each result is capped at 40 KiB (about 10k tokens, the Codex default).
   - The middle is removed with a marker: head, `…N bytes truncated…`, tail.
   - The same cap applies when old events are replayed, so existing conversations with 64 KiB `fs.read` results shrink without rewriting the event log.
   - It is deterministic, so the cached prefix stays stable.
4. **ChatGPT adapter: drop the handoff's `prompt_cache_breakpoint` code and its 400 fallback. Send `prompt_cache_key` = conversation key (`replyTo`) instead.** It reaches the adapter through `ctx`, the same way `WorkdirFrom` works. Keep the GPT‑6.1 Sol 1M window.

## Tools

**`file.list(path=".")`**: unchanged behaviour from `fs.list`; 200 entries.

**`file.read(path, offset=1, limit=2000)`**
- Output is `N|line`. Each line is capped at 2000 chars with `… [line truncated]`.
- The total is capped at 32 KiB, cut at the last whole line. On a cut it appends `[truncated; continue with offset=N]`.
- A file over 256 KiB read without an explicit offset/limit is refused: "use file.search or offset/limit".
- Kept from `fs`: chat-folder scope, credential deny list, the `os.Root` open plus `SameFile` check, non-UTF-8 refusal, and trust by source extension (rule 4).

**`file.search(pattern, path=".", glob, mode=files|content|count, limit)`**
- Runs `rg --no-config --color never --max-columns 300 --max-columns-preview -e <pattern> [-g <glob>] -- <resolved path>`, with cwd = chat folder.
- Modes:
  - `files`: `-l`, default limit 100.
  - `content`: `-n`, default limit 50 lines, grouped by file.
  - `count`: `-c`.
- rg defaults stay on: hidden and gitignored files are skipped, and symlinks are not followed.
- Every output path is filtered again through the deny list.
- 10 s timeout, 16 KiB output cap, plus `[more results; narrow path or glob]`.
- A content match in a non-source file marks the result untrusted.

**Git tools (read-only)**, the same way Claude Code auto-allows read-only git.
- They live in package `adapters/tools/local/gitread`, and reuse `readfile`'s chat-folder resolver, deny list and exec helper (exported).
- Each tool runs `git` with a fixed subcommand and fixed argv, never a shell. The model fills only the validated fields.
- All four are tier 0. Each output is capped at 16 KiB.

| Tool | Runs |
|---|---|
| `git.status()` | `git status --porcelain=v1 -b` |
| `git.diff(ref?, path?, staged?, stat?)` | `git diff [--cached] [--stat] [<ref>] -- [<path>]` |
| `git.log(limit=20, path?, ref?)` | `git log --oneline --decorate -n <limit> [<ref>] -- [<path>]` |
| `git.show(ref, path?, stat?)` | `git show [--stat] <ref> -- [<path>]` |

Guards (a repo's own `.git/config` is untrusted and can run programs):
- Every call runs as `git --no-pager -c core.fsmonitor=false -c core.hooksPath=/dev/null -c diff.external= --no-optional-locks`.
- Diff and show also get `--no-ext-diff --no-textconv`.
- Env: `GIT_CONFIG_NOSYSTEM=1`, `GIT_TERMINAL_PROMPT=0`.
- `ref` and `path` are refused when they start with `-`. That blocks `--output=`, which writes a file.
- `path` goes through the same chat-folder scope as `file.read`.
- Paths matching the deny list are dropped from the output.

Trust *(Claude's call)*:
- `git.status` and `--stat` output: trusted, because they are names only, like `file.list`.
- `git.diff`, `git.log`, `git.show`: untrusted. Commit messages and diffs can carry text written by others.

**Tool descriptions steer the model.** Claude Code and Hermes rely on this instead of a rule: "Search first with file.search, then read only the lines you need with offset/limit." The extra line the handoff added to the chat goal is dropped.

## Steps (each ends with `make gate` green)

1. `git mv adapters/tools/local/fs adapters/tools/local/readfile`, then rename tools to `file.*`. Update `main.go`, `policy.yaml`, and CLAUDE.md rule 4. Drop the handoff's Go `glob`/`grep` code.
   - Verify: the tests renamed from `fs_test.go` pass.
2. `file.read` offset/limit, line numbers, caps, `next_offset`, 256 KiB refusal.
   - Verify: table tests for range, line cap, total cap, big-file refusal, deny list.
3. `file.search` on `rg`.
   - Verify: tests on a temp tree cover the three modes, glob, limit, denied `.env` not returned, hidden skipped, missing `rg` gives a clear error, and timeout.
4. `gitread`: `git.status`, `git.diff`, `git.log`, `git.show`.
   - Verify: tests on a temp repo for each tool; a ref or path starting with `-` is refused; a program set in the repo config as `core.fsmonitor` or `diff.external` does not run; a path outside the chat folder is refused; the output cap holds.
5. Record-time cap in `app.appendResult`, plus the same cap on replay.
   - Verify: an app test where a 100 KiB tool result is stored and replayed at ≤ 40 KiB with the marker, and a legacy 64 KiB event is bounded on replay.
6. ChatGPT: remove breakpoints, the fallback, and the `fs.read` check; add `prompt_cache_key`.
   - Verify: a request-shape test where the key equals the conversation key and is identical across two steps of one conversation.
7. Live check, only when the owner agrees to spend quota. Re-run "rescan this repo" on `chatgpt-sub`.
   - Verify: input tokens per request, and `cached_tokens` > 0 from request 2 on.

## Uncertain

- **`prompt_cache_key` on the ChatGPT plan route.** Codex sends it on that route, but our adapter comment says the route rejects some fields. If it returns a 400, drop the field; don't retry blindly. Verify in step 6.
- **History with old tool names.** Old conversations hold `fs.read` calls whose names are no longer in the tool list. Whether the Responses API accepts that in `input` is unverified. If not, map `fs.*` to `file.*` on replay in `app` (one table, no adapter knowledge).
- **The 40 KiB / 32 KiB / 16 KiB caps** are borrowed defaults, not measured for Alfred. Tune them after step 6.
